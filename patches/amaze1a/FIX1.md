# RENDER2N AMaZE1A FIX1

28 September 2026. Isolated source-reconstruction candidate, not a promoted photographic fix.

Parent: RENDER2N commit 89da9e2a1e46d815962a8f08e7a4f4a762d944cc. The application is reconstructed from the same hash-verified RENDER2M baseline as before. Production/capture and the original RENDER2N branch remain unchanged.

## TAIL1A: physical-bottom reflection

An additional deterministic synthetic sweep found 56 mismatches among 80 full-frame versus banded comparisons in the old adapter (four CFAs, frame heights 257 through 276). The failing heights were 258 through 271. These are synthetic RAW-pattern results, not measurements of a user's photograph.

When fewer than 16 physical rows remain beyond a band, AMaZE's reflection bookkeeping uses its window end rather than the physical image end. FIX1 extends that computation to the physical bottom, with 16 additional scratch rows per output plane. Only the original requested rows are emitted, so the Java band schedule and global tile lattice remain unchanged.

## SCRATCH1A: independent tile initialization

Testing the non-SSE source branch exposed worker-count-dependent output on nonconstant synthetic Bayer input. An inspected example differed in six channel samples by up to 12 unsigned-16-bit codes. Resetting the private tile workspace before each independent tile removed the observed dependency in the expanded suite. Do not interpret this as photographic validation or proof about every possible RAW input.

The pristine upstream source and license are retained. A separate amaze_m10r_fix1.cc is generated by a single, hash-checked insertion of workspace initialization. Both original and compiled-source hashes and the explicit modification are recorded in M10R_FIX1_PROVENANCE.json. This is an engineering correction, not firmware-derived Leica behavior or a colour filter.

## Required gates

The real algorithm, not a test double, is compiled for x86 SSE and for its non-SSE branch. Each runs 188 synthetic cases including 80 short-tail cases, full-frame versus 128/256-row bands, one versus four workers, original measured CFA sample retention, and unchanged 16-pixel border values. Both paths also run address/undefined-behaviour sanitizers. Non-sanitized runs include a 4096x3072 smoke test. The actual JNI wrapper runs 73 assertions over 24 repeated sessions. A host non-SSE build exercises the source branch used on ARM but is not execution on Android hardware.

The Android workflow must pass all gates and compile the actual APK before packaging. Its provenance still reports phoneValidated=false and sameRawPhotographicReplayPerformed=false until those tests actually happen.

No RAW noise correction, directional chroma filtering, global magenta suppression, HDR, exposure adjustment, sensor-specific look, or M10-R colour/tone retuning is added. Existing preview, meter, capture, DNG, native target renderer and existing assets are checked unchanged. Final photograph pixels are expected to differ because the demosaic input changes; unchanged target code is not a promise of identical final colour.

This is not a speed optimization. It retains the EA border reference calculation and adds AMaZE source storage and per-tile clearing. Phone memory, latency, successive captures and same-RAW photographic quality remain pending. These adapter findings do not establish the cause of any previously supplied photograph's fringes.
